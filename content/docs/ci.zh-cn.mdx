[setup-birdcc](https://github.com/bird-chinese-community/setup-birdcc) 是一个 composite 类型的 GitHub Action。它检出仓库，安装 Node.js 与 pnpm，并可以安装 BIRD 2 或 BIRD 3、Rust 工具链以及仓库的依赖。这个 action 不运行 `birdcc`，命令由工作流在自己的步骤中运行。发布标签为 `v1.0.0`。

## 基本工作流 [#basic-workflow]

下面的工作流要求仓库根目录有一份带 `main` 的 `bird.config.json`：

```yaml title=".github/workflows/bird.yml"
name: BIRD config

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - name: Set up BIRD config tooling
        id: setup
        uses: bird-chinese-community/setup-birdcc@v1.0.0
        with:
          install-dependencies: "false"
          cache-turbo: "false"

      - name: Install birdcc
        run: npm install --global @birdcc/cli@1.0.0

      - name: Lint and parse with BIRD
        run: birdcc lint --bird

      - name: Check formatting
        run: birdcc fmt --check
```

- setup 步骤安装 BIRD 2，并为后续步骤设置环境变量 `BIRD_BIN`。`birdcc lint --bird` 对入口文件运行 `"$BIRD_BIN" -p -c <file>`。
- `install-dependencies: "false"` 跳过 `pnpm install --frozen-lockfile`。这条命令需要 `working-directory` 中有 `package.json` 与 `pnpm-lock.yaml`。
- `cache-turbo: "false"` 跳过 Turbo 缓存。只有 Turborepo 项目才需要保留默认值 `"true"`。
- 出现级别为 `error` 的诊断或命令失败时，`birdcc lint` 以退出码 1 结束。所有规则默认报告 `warning` 或 `info`。要让任务在出现 lint 问题时失败，按[让 CI 在出现问题时失败](./linting.mdx#fail-on-findings)提升 `bird.config.json` 中规则组的级别。
- 文件需要格式化时，`birdcc fmt --check` 以退出码 1 结束。

不做全局安装时，用 `pnpm dlx` 或 `npx` 运行 CLI。`pnpm dlx` 运行包中的 `birdcc` 可执行文件，所以参数直接以命令名开头：

```sh
pnpm dlx @birdcc/cli@1.0.0 lint --bird
npx @birdcc/cli@1.0.0 fmt --check
```

仓库有 `package.json` 时，把 `@birdcc/cli` 加入 `devDependencies` 并提交 `pnpm-lock.yaml`。保持 `install-dependencies` 为 `"true"`，然后运行 `pnpm exec birdcc lint`。

要把 action 固定到某个提交，使用该标签对应的提交：`bird-chinese-community/setup-birdcc@8457cfc198d2e3de7cb1cf3bf441772ef895e6c0`。

## 输入 [#inputs]

所有输入都是字符串。布尔类型的输入取 `"true"` 或 `"false"`。action 会校验输入，值不在允许范围内时以错误结束。

| 输入                          | 默认值                                              | 说明                                                                        |
| ----------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------- |
| `checkout`                    | `"true"`                                            | 运行 `actions/checkout`。                                                   |
| `fetch-depth`                 | `"0"`                                               | 检出时的抓取深度，非负整数。`"0"` 抓取完整历史。                            |
| `submodules`                  | `"false"`                                           | 检出时的子模块模式：`"false"`、`"true"` 或 `"recursive"`。                  |
| `submodule-paths`             | 空                                                  | 以深度 1 初始化的子模块路径，用换行或逗号分隔。只能是不含 `..` 的相对路径。 |
| `submodule-timeout`           | `"120"`                                             | 每次子模块 Git 操作的超时时间，单位为秒。                                   |
| `node-version`                | `"22"`                                              | 传给 `actions/setup-node` 的 Node.js 版本。                                 |
| `pnpm-version`                | `"10.18.3"`                                         | 传给 `pnpm/action-setup` 的 pnpm 版本。                                     |
| `registry-url`                | `"https://registry.npmjs.org"`                      | 传给 `actions/setup-node` 的 npm registry。                                 |
| `working-directory`           | `"."`                                               | 安装依赖与 Turbo 缓存路径所用的目录，相对于工作区。                         |
| `install-dependencies`        | `"true"`                                            | 运行 `install-command` 并缓存 pnpm store。                                  |
| `install-command`             | `"pnpm install --frozen-lockfile --prefer-offline"` | 安装依赖的命令。                                                            |
| `cache-turbo`                 | `"true"`                                            | 恢复并保存 Turbo 缓存。                                                     |
| `turbo-cache-path`            | `".turbo"`                                          | Turbo 缓存路径，相对于 `working-directory`。                                |
| `install-rust`                | `"false"`                                           | 用 `dtolnay/rust-toolchain` 安装 Rust 工具链。                              |
| `rust-toolchain`              | `"stable"`                                          | 要安装的 Rust 工具链。                                                      |
| `rust-components`             | `"rustfmt,clippy"`                                  | 要安装的 Rust 组件，用逗号分隔。                                            |
| `rust-targets`                | `"wasm32-unknown-unknown"`                          | 要安装的 Rust 目标，用逗号分隔。                                            |
| `install-bird`                | `"true"`                                            | 安装 BIRD 可执行文件。                                                      |
| `bird-version`                | `"2"`                                               | BIRD 主版本：`"2"` 或 `"3"`。                                               |
| `bird-package-source`         | `"auto"`                                            | BIRD 的软件包来源：`"auto"`、`"ubuntu"` 或 `"cznic"`。                      |
| `harden-runner`               | `"false"`                                           | 最先运行 `step-security/harden-runner`。                                    |
| `harden-runner-egress-policy` | `"audit"`                                           | 传给 `harden-runner` 的出站策略：`"audit"` 或 `"block"`。                   |

## 输出 [#outputs]

| 输出                   | 说明                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------- |
| `bird-bin`             | BIRD 可执行文件的路径。`install-bird` 为 `"false"` 或 runner 不是 Linux 时为空。          |
| `bird-version`         | `bird --version` 的输出。`install-bird` 为 `"false"` 或 runner 不是 Linux 时为空。        |
| `turbo-cache-hit`      | `actions/cache` 以完全匹配的键恢复 Turbo 缓存时为 `true`。                                |
| `changed-config-files` | pull request 中变更的 BIRD 配置文件，每行一个路径。见[只检查变更的文件](#changed-files)。 |

BIRD 安装步骤运行时，还会把值与 `bird-bin` 相同的 `BIRD_BIN` 写入本任务后续步骤的环境变量。

## BIRD 2 与 BIRD 3 [#bird-versions]

| `bird-version` | `bird-package-source`  | 安装的软件包                                                  |
| -------------- | ---------------------- | ------------------------------------------------------------- |
| `"2"`          | `"auto"` 或 `"ubuntu"` | 来自 runner 的 Ubuntu 软件源的 `bird2`                        |
| `"2"`          | `"cznic"`              | 来自 CZ.NIC 软件源 `https://pkg.labs.nic.cz/bird2` 的 `bird2` |
| `"3"`          | `"auto"` 或 `"cznic"`  | 来自 CZ.NIC 软件源 `https://pkg.labs.nic.cz/bird3` 的 `bird3` |
| `"3"`          | `"ubuntu"`             | 不安装，action 以错误结束。                                   |

- action 只在 Linux runner 上安装 BIRD。在其他 runner 上，它输出一条警告，`bird-bin` 与 `BIRD_BIN` 为空。不要在这类 runner 上使用 `birdcc lint --bird`。
- `/usr/sbin/bird` 或 `/usr/local/sbin/bird` 已存在且 `--version` 运行成功时，action 直接使用这个可执行文件，不安装软件包。在自托管 runner 上，这个可执行文件的主版本可能与 `bird-version` 不同。

要用两个版本分别检查同一份配置，使用矩阵：

```yaml title=".github/workflows/bird.yml"
jobs:
  check:
    name: BIRD ${{ matrix.bird-version }}
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        bird-version: ["2", "3"]
    steps:
      - name: Set up BIRD ${{ matrix.bird-version }}
        uses: bird-chinese-community/setup-birdcc@v1.0.0
        with:
          install-dependencies: "false"
          cache-turbo: "false"
          bird-version: ${{ matrix.bird-version }}

      - name: Install birdcc
        run: npm install --global @birdcc/cli@1.0.0

      - name: Lint and parse with BIRD
        run: birdcc lint --bird
```

## 只检查变更的文件 [#changed-files]

输出 `changed-config-files` 列出 pull request 新增、复制、修改或重命名的配置文件。只有满足下列条件时，action 才计算这份列表：

- `checkout` 为 `"true"`，且 `fetch-depth` 为 `"0"`。两者都是默认值。
- 事件带有 pull request 数据，例如 `pull_request` 或 `pull_request_target`。其他事件（例如 `push`）的列表为空。

action 比较 pull request 的基准提交与 `github.sha`，保留文件名以 `.conf`、`.bird`、`.bird2` 或 `.bird3` 结尾的路径。路径相对于仓库根目录，每行一个。列表不包含已删除的文件。

```yaml title=".github/workflows/bird.yml"
- name: Check changed files
  if: steps.setup.outputs.changed-config-files != ''
  env:
    CHANGED_FILES: ${{ steps.setup.outputs.changed-config-files }}
  run: |
    while IFS= read -r file; do
      birdcc fmt "$file" --check
      birdcc lint "$file"
    done <<< "$CHANGED_FILES"
```

这个步骤使用[基本工作流](#basic-workflow)中的 `setup` id 与 `birdcc` 安装步骤。

- `birdcc lint <file>` 分析为该文件探测到的入口文件的 include 图，输出可能包含该图中其他文件的诊断。[跨文件分析](./linting.mdx#cross-file)说明探测方式。
- 这个步骤不使用 `--bird`。`--bird` 对传入的文件运行 `bird -p`，文件用到其他文件中的定义时，BIRD 会报告错误。请在单独的步骤中对入口文件运行 `birdcc lint --bird`。

## 不使用 action [#without-action]

CLI 需要 Node.js 22 或更新版本。BIRD 仅在使用 `--bird` 时需要。与基本工作流一样，这个工作流要求有一份带 `main` 的 `bird.config.json`。

```yaml title=".github/workflows/bird.yml"
name: BIRD config

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22

      - name: Install birdcc
        run: npm install --global @birdcc/cli@1.0.0

      - name: Install BIRD 2
        run: |
          sudo apt-get update
          sudo apt-get install -y bird2

      - name: Lint and parse with BIRD
        run: birdcc lint --bird
        env:
          BIRD_BIN: /usr/sbin/bird

      - name: Check formatting
        run: birdcc fmt --check
```

Ubuntu 的 `bird2` 软件包把可执行文件安装到 `/usr/sbin/bird`。不使用 `--bird` 时，去掉安装 BIRD 的步骤。

要保存一次运行的 JSON 报告，用 `birdcc lint --format json > birdcc-lint.json` 写入文件。[JSON 输出](./reference/cli.mdx#json-output)参考列出各字段。
