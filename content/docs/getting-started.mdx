## Requirements

| Tool                                                         | Requirement                                                                                   |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| `birdcc` from `@birdcc/cli`                                  | Node.js 22 or newer.                                                                          |
| BIRD2 LSP for VS Code                                        | VS Code 1.100 or newer. The extension contains the language server and does not need Node.js. |
| `bird -p` checks (`birdcc lint --bird`, fallback validation) | BIRD 2 or BIRD 3 on the same machine. Lint rules and editor features do not need BIRD.        |

## Install and check a configuration

<Steps>

<Step>

### Install the editor extension

BIRD2 Extension Pack (`BIRDCC.bird2-extension-pack`) installs two extensions: BIRD2 LSP (`BIRDCC.bird2-lsp`), which contains the language server, and BIRD2 Configuration (`BIRDCC.vscode-bird2-conf`), which provides syntax highlighting.

<Tabs items={["VS Code Marketplace", "Open VSX", "Command line"]}>

<Tab value="VS Code Marketplace">

In VS Code, open the Extensions view, search for `BIRD2 Extension Pack` and select **Install**. The Marketplace page is [BIRDCC.bird2-extension-pack](https://marketplace.visualstudio.com/items?itemName=BIRDCC.bird2-extension-pack).

</Tab>

<Tab value="Open VSX">

VSCodium and other editors that install extensions from Open VSX use the same extension pack: [BIRDCC/bird2-extension-pack](https://open-vsx.org/extension/BIRDCC/bird2-extension-pack). Search for `BIRD2 Extension Pack` in the Extensions view of the editor.

</Tab>

<Tab value="Command line">

```sh
code --install-extension BIRDCC.bird2-extension-pack
```

</Tab>

</Tabs>

VS Code enables the extension only in a trusted workspace. For Neovim, Vim, Helix and other editors, see [Other editors](./editors/other-editors.mdx).

</Step>

<Step>

### Install the CLI

```sh
npm install --global @birdcc/cli
```

Run `birdcc --help` to check the installation. It lists the commands `lint`, `fmt`, `lsp` and `init`. To pin the version in a project, run `npm install --save-dev @birdcc/cli` and call the command as `npx birdcc`.

</Step>

<Step>

### Check a configuration file

This configuration refers to a filter that it does not define:

```bird2 title="bird.conf"
router id 192.0.2.1;

protocol device {
}

protocol bgp upstream {
  local as 65001;
  neighbor 192.0.2.2 as 65002;
  ipv4 {
    import filter peer_in;
    export none;
  };
}
```

Run the linter in the directory of the file:

```sh
birdcc lint bird.conf
```

```text
WARNING sym/filter-required [file:///srv/bird/bird.conf] 10:19 Protocol 'upstream' references unknown filter 'peer_in'
```

Each line shows the severity, the rule code, the file URI, the line and column, and the message. By default, the `sym`, `cfg`, `net` and `type` rules report warnings and the `bgp` and `ospf` rules report information, so this run exits with status 0. `birdcc lint` exits with status 1 when a diagnostic has severity `error` or when the command fails. [Linting](./linting.mdx) shows how to raise rule severities so that lint fails a CI job.

`birdcc lint` follows the `include` statements of the file. Add `--bird` to also run `bird -p` on the file.

</Step>

<Step>

### Create bird.config.json

To see the candidates and the file content without writing the file, run `birdcc init --dry-run` first. Then write the file:

```sh
birdcc init --write
```

```text
Created bird.config.json
  Entry: bird.conf (single, confidence: 100%)
```

```json title="bird.config.json"
{
  "$schema": "https://raw.githubusercontent.com/bird-chinese-community/BIRD-LSP/main/schemas/bird.config.schema.json",
  "main": "./bird.conf",
  "formatter": {
    "indentSize": 2
  }
}
```

`birdcc init` scans the `.conf` files below the current directory and writes the detected entry file as `main`. When it finds several independent entry files, it writes `workspaces` instead. It adds `formatter.indentSize` when the entry files use an indentation of 2, 4 or 8 spaces.

Without a file argument, `birdcc lint` lints the `main` entry and its include graph, and `birdcc fmt` checks the formatting of the `main` file:

```sh
birdcc lint
birdcc fmt
```

The language server reads the same file. [Project configuration](./project-configuration.mdx) describes the keys, entry detection and include resolution.

</Step>

</Steps>
