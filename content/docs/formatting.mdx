`birdcc fmt` formats one BIRD configuration file with `@birdcc/formatter`. The command comes from the `@birdcc/cli` package and requires Node.js 22 or newer.

The formatter indents each line by its block depth and normalizes whitespace. It does not wrap, join, split or reorder lines.

```sh
npm install --global @birdcc/cli
```

## Check and write files [#check-and-write]

Check a file. The command does not change the file:

```sh
birdcc fmt bird.conf
```

```text
Format check failed. Run `birdcc fmt <file> --write` to fix.
```

The command exits with status 1 when the file needs formatting and with status 0 when it does not. `--check` gives the same result explicitly.

Write the formatted text back to the file:

```sh
birdcc fmt bird.conf --write
```

Example input and the result of `--write`:

```bird2 title="bird.conf (before)"
protocol bgp upstream {
local as 65001;
    neighbor 192.0.2.2 as 65002;   # transit


ipv4 {
import all;
export where net ~ [ 10.0.0.0/8+ ];
};
}
```

```bird2 title="bird.conf (after)"
protocol bgp upstream {
  local as 65001;
  neighbor 192.0.2.2 as 65002; # transit

  ipv4 {
    import all;
    export where net ~ [ 10.0.0.0/8+ ];
  };
}
```

- Without a file argument, `birdcc fmt` uses the `main` entry of the nearest `bird.config.json`, or `bird.conf` when `main` is not set. The command formats only that file, not its include graph.
- When `bird.config.json` sets `workspaces`, pass the file to format.
- `--json` prints `{ "changed", "filePath" }` instead of the message. The exit status is the same.
- `birdcc fmt` rejects `--write` together with `--check`.

The [`fmt` reference](./reference/cli.mdx#fmt) lists every message and exit status. [CI](./ci.mdx) shows `birdcc fmt --check` in a GitHub Actions workflow.

## What the formatter changes [#rules]

Both engines apply these rules:

- Indent each line by its nesting depth of `{ }` and `[ ]` blocks in the Tree-sitter syntax tree. Braces in strings and comments do not change the depth.
- Collapse consecutive blank lines into one and remove blank lines at the end of the file.
- Convert `\r\n` and `\r` line endings to `\n`.
- Remove trailing spaces and tabs, except after a comment.
- End the file with one `\n`.
- Keep the lines of a multi-line comment unchanged, including their indentation.

On the other lines, the formatter also makes these changes:

- Write `name{` as `name {`.
- Remove the spaces before a final `;`.
- Put one space between the code and a trailing `#` comment.

Lines whose code contains `if`, `then`, `else`, `return` or one of `~ & | ? : ( [ ]` are expression lines. The formatter changes only their indentation and the space before a trailing comment.

## Engines [#engines]

`@birdcc/formatter` has two engines that apply the same rules:

| Engine             | Implementation                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------- |
| `dprint` (default) | The Rust plugin `@birdcc/dprint-plugin-bird`, compiled to WebAssembly and run through `@dprint/formatter`. |
| `builtin`          | TypeScript code in `@birdcc/formatter` that uses the syntax tree of `@birdcc/parser`.                      |

The `builtin` engine handles these lines like expression lines and changes only their indentation and the space before a trailing comment:

- Lines longer than `lineWidth`.
- Lines with a parse error.
- Statements in `filter` and `function` bodies.
- Protocol statements that the parser keeps as plain text.
- `import where` and `export where` statements.

The `dprint` engine keeps the spacing before the comment of an expression line that is longer than `lineWidth`.

For example, in a `filter` body the `dprint` engine writes `bgp_med = 100   ;` as `bgp_med = 100;`. The `builtin` engine keeps the line as written.

Select the engine for one run with `--engine`, or for every run with `formatter.engine` in `bird.config.json`:

```sh
birdcc fmt bird.conf --write --engine builtin
```

When the `dprint` engine fails, the result depends on the engine setting:

- Neither `--engine` nor `formatter.engine` is set: birdcc formats the file again with the `builtin` engine and prints `Formatting with @birdcc/formatter failed, falling back to builtin formatter: <reason>` to stderr.
- You set the engine: birdcc reports the failure and exits with status 1.

## Safe mode [#safe-mode]

Safe mode is on by default. Before the formatter returns changed text, it parses the input and the output with `@birdcc/parser` and compares the two results:

- The declaration tree without source positions, with whitespace in text values collapsed.
- The code and the message of each parse error.

When the results differ, formatting fails with `Formatter safe mode rejected output because semantic fingerprint changed` and the file stays unchanged.

The `dprint` engine also runs a check inside the plugin. It compares the node kinds, child counts, missing nodes and token text of the two Tree-sitter trees, and fails with `Formatter safe mode rejected output because syntax or token content changed`.

- The formatter formats a file with syntax errors when its parse errors are the same before and after formatting.
- When the output is identical to the input, the check does not run.

To turn safe mode off, set `"safeMode": false` in the `formatter` section of `bird.config.json`.

## Formatter options [#options]

`birdcc fmt`, the language server and the VS Code extension read the `formatter` section of `bird.config.json`:

```json title="bird.config.json"
{
  "main": "bird.conf",
  "formatter": {
    "engine": "dprint",
    "indentSize": 4,
    "lineWidth": 100,
    "safeMode": true
  }
}
```

| Key          | Default    | Values                  | Description                                                                                                     |
| ------------ | ---------- | ----------------------- | --------------------------------------------------------------------------------------------------------------- |
| `engine`     | `"dprint"` | `"dprint"`, `"builtin"` | Formatter engine. See [Engines](#engines).                                                                      |
| `indentSize` | `2`        | 1 to 16                 | Spaces for each indentation level.                                                                              |
| `useTabs`    | `false`    | `true`, `false`         | Indent with one tab for each level.                                                                             |
| `lineWidth`  | `80`       | 20 to 1000              | Lines longer than this value keep more of their text. See [Engines](#engines). The formatter never wraps lines. |
| `safeMode`   | `true`     | `true`, `false`         | Reject output whose parse result differs from the input. See [Safe mode](#safe-mode).                           |

`birdcc fmt` has no command-line options for indentation or line width. `birdcc init` adds `formatter.indentSize` when the entry files use an indentation of 2, 4 or 8 spaces.

The [configuration reference](./reference/configuration.mdx#formatter) describes the complete `formatter` section.

## Use the dprint plugin [#dprint]

The dprint CLI can load `@birdcc/dprint-plugin-bird` directly, for example in a repository where dprint already formats other files.

`npm:` plugin specifiers and additive `associations` require dprint 0.55.0 or newer. dprint 0.64.3 produces the results shown in the examples below.

<Steps>

<Step>

### Install dprint and the plugin

```sh
npm install --save-dev dprint @birdcc/dprint-plugin-bird
```

</Step>

<Step>

### Add the plugin to dprint.json

```json title="dprint.json"
{
  "birdcc": {
    "lineWidth": 100,
    "indentWidth": 2,
    "useTabs": false,
    "safeMode": true
  },
  "plugins": ["npm:@birdcc/dprint-plugin-bird/dist/dprint-plugin-bird.wasm"]
}
```

The `npm:` specifier without a version loads the package from `node_modules`. dprint searches upward from the directory of `dprint.json`.

</Step>

<Step>

### Check and format the files

```sh
npx dprint check
npx dprint fmt
```

`dprint check` prints a diff for each file that needs formatting and exits with a non-zero status (20 with dprint 0.64.3). `dprint fmt` writes the files.

</Step>

</Steps>

The plugin options go in the `birdcc` object of `dprint.json`. dprint does not read `bird.config.json`.

| Key           | Default                                             | Description                                                                                                        |
| ------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `lineWidth`   | `lineWidth` of the dprint configuration, else 80    | An expression line longer than this value also keeps the spacing before its comment. The plugin never wraps lines. |
| `indentWidth` | `indentWidth` of the dprint configuration, else 2   | Spaces for each indentation level. The key in `bird.config.json` is `indentSize`.                                  |
| `useTabs`     | `useTabs` of the dprint configuration, else `false` | Indent with one tab for each level.                                                                                |
| `safeMode`    | `true`                                              | Run the check inside the plugin. The `@birdcc/parser` comparison of `@birdcc/formatter` does not run.              |

- An unknown key in the `birdcc` object stops dprint with `Unknown property in configuration`. The JSON schema is [`schemas/dprint-plugin-bird.schema.json`](https://github.com/bird-chinese-community/BIRD-LSP/blob/main/schemas/dprint-plugin-bird.schema.json).
- The plugin formats every file with the extension `.conf` or `.bird`. To exclude other `.conf` files or to add file names, set `associations`:

  ```json title="dprint.json"
  {
    "birdcc": {
      "associations": ["!**/nginx.conf", "**/*.bird3"]
    }
  }
  ```

- Two other plugin references load the same module:
  - A file path: `"./node_modules/@birdcc/dprint-plugin-bird/dist/dprint-plugin-bird.wasm"`
  - A pinned version that dprint downloads from the npm registry: `"npm:@birdcc/dprint-plugin-bird@1.0.0/dist/dprint-plugin-bird.wasm"`

## Format in an editor [#editors]

The editor integrations use `@birdcc/formatter` and read the `formatter` section of `bird.config.json`.

The editor integrations do not format a `.conf` file without BIRD content, for example an `nginx.conf`. [File association](./editors/vscode.mdx#file-association) lists the conditions.

<Tabs items={["VS Code", "Other editors"]}>

<Tab value="VS Code">

BIRD2 LSP provides Format Document and Format Selection, and sets `editor.defaultFormatter` to `BIRDCC.bird2-lsp` for the `bird2` language. Format Selection formats the whole file and applies only the edits inside the selection.

The extension takes each option from the first source that sets it:

1. The `formatter` section of `bird.config.json`.
2. The settings `bird2-lsp.formatter.engine` and `bird2-lsp.formatter.safeMode`.
3. The tab size and the indentation type of the editor.

`lineWidth` comes only from `bird.config.json`, with the default 80. [VS Code settings](./editors/vscode.mdx#settings) lists the settings.

When formatting fails, the extension leaves the file unchanged and the `BIRD2 LSP` output channel shows the reason.

</Tab>

<Tab value="Other editors">

The language server answers `textDocument/formatting` with one edit for the whole document. It does not support range formatting. In Neovim, `vim.lsp.buf.format()` sends the request.

The server takes each option from the first source that sets it:

1. The `formatter` section of `bird.config.json`.
2. The `formatter` object of the editor settings that the client sends to the server.
3. `tabSize` and `insertSpaces` of the formatting request.

When formatting fails, the server returns the error `BIRD formatting failed: <reason>`. [Language server settings](./reference/language-server.mdx#settings) lists the settings.

</Tab>

</Tabs>
