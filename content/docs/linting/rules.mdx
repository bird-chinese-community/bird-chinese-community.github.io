`@birdcc/linter` checks a BIRD configuration against 32 rules in six groups. `birdcc lint` and the language server report the same rules. A rule code has the form `<group>/<name>`, for example `sym/filter-required`.

| Group           | Rules | Default severity | Checks                                                                                          |
| --------------- | ----- | ---------------- | ----------------------------------------------------------------------------------------------- |
| [`sym`](#sym)   | 7     | `warning`        | Definitions of and references to protocols, templates, filters, functions, tables and variables |
| [`cfg`](#cfg)   | 9     | `warning`        | Configuration structure, option values and value types                                          |
| [`net`](#net)   | 4     | `warning`        | Prefix literals and prefix lengths                                                              |
| [`type`](#type) | 3     | `warning`        | Types in filter and function expressions                                                        |
| [`bgp`](#bgp)   | 5     | `info`           | BGP protocol settings                                                                           |
| [`ospf`](#ospf) | 4     | `info`           | OSPF areas                                                                                      |

A diagnostic with the severity `error` makes `birdcc lint` exit with status 1. [Change severities](#severity) shows how to raise the rule groups to `error`.

## Symbols (`sym`) [#sym]

| Rule                      | Default   | Reported for                                                                                                                                                                                                                                                 |
| ------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `sym/undefined`           | `warning` | A `from` template that is not defined, or an include that the analysis cannot load                                                                                                                                                                           |
| `sym/duplicate`           | `warning` | A second definition with the same kind and name                                                                                                                                                                                                              |
| `sym/proto-type-mismatch` | `warning` | A protocol that inherits from a template of another protocol type                                                                                                                                                                                            |
| `sym/filter-required`     | `warning` | An `import filter` or `export filter` clause without a name, or with the name of an undefined filter                                                                                                                                                         |
| `sym/function-required`   | `warning` | A call to a function that is not declared and is not in the list of built-in functions of the linter. The list contains `roa_check` and `defined`. It does not contain `aspa_check`, so a call to `aspa_check` is reported                                   |
| `sym/table-required`      | `warning` | A `table` clause without a name, or with the name of an undefined table                                                                                                                                                                                      |
| `sym/variable-scope`      | `warning` | An assignment in a filter or function to a name that the body does not declare before it. Assignments to `gw`, `ifname`, `onlink`, `dest`, `krt_prefsrc`, `bgp_local_pref`, `bgp_next_hop`, `bgp_next_hop_ll`, `preference` and `validated` are not reported |

## Configuration (`cfg`) [#cfg]

| Rule                        | Default   | Reported for                                                                                                                                                                                                                     |
| --------------------------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cfg/no-protocol`           | `warning` | A file with no `protocol` and no `define`, `include`, `function`, `template` or `table` declaration                                                                                                                              |
| `cfg/missing-router-id`     | `warning` | A file with a BGP protocol that is not based on a template, and with no `router id`, `include` or `define`                                                                                                                       |
| `cfg/syntax-error`          | `warning` | Any parse issue from `@birdcc/parser`                                                                                                                                                                                            |
| `cfg/value-out-of-range`    | `warning` | `local as` or `neighbor ... as` outside 1–4294967294; a channel `limit` or `max prefix` outside 0–4294967295; `hold` (3–65535), `keepalive` (1–65535) or `ttl` (1–255) out of range in a statement that the parser keeps as text |
| `cfg/switch-value-expected` | `warning` | A value that is not a boolean after `passive`, `stub`, `bfd`, `enabled`, `disabled`, `check link`, `deterministic med` or a channel `keep filtered`                                                                              |
| `cfg/number-expected`       | `warning` | A value that is not a number for one of the options of `cfg/value-out-of-range`. Constant names with an upper-case letter or `_` are accepted, and so are `internal`, `external`, `ibgp` and `ebgp` for AS values                |
| `cfg/incompatible-type`     | `warning` | A `neighbor` address that is not an IP address (or not a prefix for `neighbor range`), or a `router id` value that `@birdcc/core` rejects                                                                                        |
| `cfg/ip-network-mismatch`   | `warning` | An IPv6 address in an unstructured `ipv4` channel option, or an IPv4 address in an `ipv6` channel option                                                                                                                         |
| `cfg/circular-template`     | `warning` | A template inheritance cycle                                                                                                                                                                                                     |

## Networks (`net`) [#net]

| Rule                        | Default   | Reported for                                                                                                                                                             |
| --------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `net/invalid-prefix-length` | `warning` | A prefix literal in a filter or function that is not valid CIDR, a length range whose minimum is larger than its maximum, or a channel `max prefix` that is not a number |
| `net/invalid-ipv4-prefix`   | `warning` | A dotted prefix whose address is not a valid IPv4 address, or a prefix whose address contains neither `.` nor `:`                                                        |
| `net/invalid-ipv6-prefix`   | `warning` | A prefix that contains `:` and whose address is not a valid IPv6 address                                                                                                 |
| `net/max-prefix-length`     | `warning` | An IPv4 prefix length or length range above 32, or a channel `max prefix` above 32 (`ipv4`) or 128 (`ipv6`)                                                              |

## Types (`type`) [#type]

| Rule                    | Default   | Reported for                                                                                                          |
| ----------------------- | --------- | --------------------------------------------------------------------------------------------------------------------- |
| `type/mismatch`         | `warning` | A typed local variable that is declared or assigned with a value of another type                                      |
| `type/not-iterable`     | `warning` | A right side of `~` that is not a `[...]` set, an `(a, b)` tuple, an IP address, a prefix, a prefix pattern or a name |
| `type/set-incompatible` | `warning` | A left side of `~` whose type is different from the type of the first element of the set literal                      |

## BGP (`bgp`) [#bgp]

| Rule                    | Default | Reported for                                                                                                                     |
| ----------------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `bgp/missing-local-as`  | `info`  | A BGP protocol without `local as` and without a template                                                                         |
| `bgp/missing-neighbor`  | `info`  | A BGP protocol without `neighbor` and without a template                                                                         |
| `bgp/missing-remote-as` | `info`  | A `neighbor` without an AS number, `internal` or `external`, in a protocol that is not based on a template                       |
| `bgp/as-mismatch`       | `info`  | A protocol with an internal neighbor and a neighbor AS number that is different from `local as`                                  |
| `bgp/timer-invalid`     | `info`  | `hold time` outside 3–65535, `keepalive time` outside 1–65535 (0 disables either timer), or `keepalive` that is not below `hold` |

## OSPF (`ospf`) [#ospf]

| Rule                     | Default | Reported for                                              |
| ------------------------ | ------- | --------------------------------------------------------- |
| `ospf/missing-area`      | `info`  | An OSPF protocol without an `area`                        |
| `ospf/backbone-stub`     | `info`  | The backbone area (`0` or `0.0.0.0`) configured as `stub` |
| `ospf/vlink-in-backbone` | `info`  | A virtual link inside the backbone area                   |
| `ospf/asbr-stub-area`    | `info`  | An ASBR declared inside a stub area                       |

## Parser and core diagnostics [#parser-and-core]

The linter reports the diagnostics of `@birdcc/parser` and `@birdcc/core` under rule codes. When the original code is different from the rule code, the message starts with the original code in brackets, for example `[semantic/duplicate-definition] protocol 'd1' is already defined`.

| Original code                                                                                | Rule code                   |
| -------------------------------------------------------------------------------------------- | --------------------------- |
| All five parser issue codes                                                                  | `cfg/syntax-error`          |
| `semantic/duplicate-definition`                                                              | `sym/duplicate`             |
| `semantic/undefined-reference`, `semantic/missing-include`                                   | `sym/undefined`             |
| `semantic/circular-template`                                                                 | `cfg/circular-template`     |
| `semantic/invalid-router-id`, `semantic/invalid-neighbor-address`, `type/unknown-expression` | `cfg/incompatible-type`     |
| `semantic/invalid-cidr`                                                                      | `net/invalid-prefix-length` |
| `type/mismatch`                                                                              | `type/mismatch`             |
| `type/undefined-variable`                                                                    | `sym/variable-scope`        |

`linter.rules` matches the rule codes, not the original codes.

## File roles [#file-roles]

The linter gives each file a role from its path and content. The role decides which rules apply.

- `bird.conf`, `bird2.conf` and `bird3.conf` are entry files. A file with a `router id` or `include` declaration is also an entry file, unless its directory marks it as a fragment or a library.
- Other files become fragments or libraries. The linter classifies them with these checks:
  - Directory and file name markers, such as `peers`, `upstream`, `filters` and `lib`
  - Whether the directory of the file or a parent directory holds an entry file
  - Whether the file declares named protocols
- A file that none of these checks classifies is an entry file.
- For fragments and libraries, the linter drops the following rules, because the definitions that these rules need are in other files:
  - `sym/undefined`
  - `sym/function-required`
  - `sym/filter-required`
  - `sym/table-required`
  - `cfg/no-protocol`
  - `cfg/missing-router-id`
- In cross-file analysis, the linter also drops `cfg/no-protocol` and `cfg/missing-router-id` for every file except the entry file.

## Change severities [#severity]

`birdcc lint` and the language server read `linter.rules` from `bird.config.json` (or its alias `birdcc.config.json`) and apply it to the diagnostics:

```json title="bird.config.json"
{
  "linter": {
    "rules": {
      "cfg/*": "error",
      "cfg/syntax-error": "off",
      "sym/filter-required": "info"
    }
  }
}
```

- A key that is equal to the rule code has priority.
- Otherwise the longest matching key that ends in `/*` applies. `cfg/*` matches every `cfg/` rule. Other wildcard forms, such as `*` alone, match no rule.
- The values are `error`, `warning`, `info` and `off`. `off` removes the diagnostic.
- `"linter": { "enabled": false }` removes all diagnostics of the static analysis.

In this example:

- Every `cfg` rule reports `error`.
- `cfg/syntax-error` reports nothing.
- `sym/filter-required` reports `info`.

To make `birdcc lint` fail on every finding of the `sym`, `cfg`, `net` and `type` groups, set them to `error`:

```json title="bird.config.json"
{
  "main": "bird.conf",
  "linter": {
    "rules": {
      "sym/*": "error",
      "cfg/*": "error",
      "net/*": "error",
      "type/*": "error"
    }
  }
}
```

[Lint configurations](./usage.mdx#fail-on-findings) shows the output of this configuration, and the [`linter` section](../configuration/reference.mdx#linter) of the configuration reference lists the other keys.

## Codes outside the rule set [#other-codes]

`birdcc lint --bird` adds two codes from BIRD validation. Both have the severity `error`:

| Code                | Reported for                                                                                                                     |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `bird/parse-error`  | An error line that the validation command (by default `bird -p`) writes to stderr                                                |
| `bird/runner-error` | A validation command that cannot start, times out, or exits with a non-zero status without stderr output, or an unsafe file path |

The language server adds codes for size limits, configuration errors and internal errors. See [Diagnostics](../editors/language-server.mdx#diagnostics) in the language server reference.
