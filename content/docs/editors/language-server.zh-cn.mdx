`@birdcc/lsp` 是面向 BIRD 2 与 BIRD 3 配置文件的 Language Server Protocol 服务器，通过 stdin 与 stdout 传输 JSON-RPC 消息。

VS Code 的 BIRD2 LSP 扩展 (extension) 内置了 `@birdcc/lsp`，其他编辑器用 `@birdcc/cli` 的 `birdcc lsp --stdio` 启动服务器。服务器需要 Node.js 22 或更新版本。

## 启动服务器 [#start]

```sh
birdcc lsp --stdio
node node_modules/@birdcc/lsp/dist/server.js --stdio
```

- `npm install --global @birdcc/cli` 提供第一条命令，`npm install @birdcc/lsp` 提供第二条命令。
- 第二条命令的路径相对于安装该包的项目。编辑器在其他目录启动服务器时，需要使用绝对路径。
- `--stdio` 是必需的。
- 服务器以 `window/logMessage` 通知把日志发送给客户端。
- 客户端发送 `exit` 或关闭 stdin 时，进程退出。之前收到过 `shutdown` 时退出码为 0，否则为 1。

[其他编辑器](../getting-started/installation.mdx#other-editors)给出 Neovim、Vim、Helix 及其他 LSP 客户端的配置。

## 功能 [#capabilities]

`initialize` 响应包含以下能力：

```json
{
  "capabilities": {
    "textDocumentSync": 2,
    "documentSymbolProvider": true,
    "hoverProvider": true,
    "definitionProvider": true,
    "referencesProvider": true,
    "documentFormattingProvider": true,
    "completionProvider": {
      "resolveProvider": false,
      "triggerCharacters": [" ", "."]
    },
    "inlayHintProvider": true
  }
}
```

| 方法                                                                             | 行为                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `textDocument/didOpen`、`textDocument/didChange`、`textDocument/didClose`        | 增量同步 (`textDocumentSync: 2`)。打开和修改文档后，在最后一次事件 120 ms 后开始分析。关闭文档时，清除其他打开的入口文件 (entry file) 不再需要的诊断 (diagnostic)。                                                                                                                                                                                                                                        |
| `textDocument/publishDiagnostics`                                                | 入口文件 include 图 (include graph) 中每个文件的诊断。见[诊断](#diagnostics)。                                                                                                                                                                                                                                                                                                                             |
| `textDocument/completion`                                                        | 14 个关键字和 4 个代码片段 (snippet)：`include`、`define`、`router id`、`protocol bgp`。include 图中声明的名称。`import filter` 与 `export filter` 之后的过滤器名 (filter name)，`table` 之后的路由表名 (table name)，`from` 之后的模板名 (template name)。在 `include "` 内补全 include 图中已用过的 include 路径。最多 10 个以已输入数字开头、来自 [ASN 数据库 (ASN database)](./asn-data.mdx)的 AS 号。 |
| `textDocument/hover`                                                             | 关键字文档，包括语法、参数和指向 BIRD User's Guide 的链接；声明摘要；AS 号详情：名称、国家和类型。                                                                                                                                                                                                                                                                                                         |
| `textDocument/definition`                                                        | include 图中任意位置同名的 protocol、模板、过滤器、函数、路由表或 `define` 常量的声明。                                                                                                                                                                                                                                                                                                                    |
| `textDocument/references`                                                        | 声明本身，以及引用某个模板的 `from` 子句。不返回过滤器、函数、路由表、protocol 和常量的其他用处。                                                                                                                                                                                                                                                                                                          |
| `textDocument/documentSymbol`                                                    | protocol、模板、过滤器、函数、`define` 常量、路由表、属性、MPLS domain、include、`router id`、`hostname` 与 `graceful restart wait`。                                                                                                                                                                                                                                                                      |
| `textDocument/formatting`                                                        | 用 `@birdcc/formatter` 格式化整个文档，返回一个文本编辑。                                                                                                                                                                                                                                                                                                                                                  |
| `textDocument/inlayHint`                                                         | ASN 数据库中存在的 AS 号之后显示国旗和 AS 号；每个函数名之后显示声明或推断出的返回类型。                                                                                                                                                                                                                                                                                                                   |
| `workspace/configuration`（服务器到客户端）                                      | 客户端支持 `workspace.configuration` 时，为每个文档请求 `bird2-lsp` 节。见[设置](#settings)。                                                                                                                                                                                                                                                                                                              |
| `workspace/didChangeConfiguration`                                               | 用 `settings["bird2-lsp"]` 或 `settings.birdcc` 替换设置，并重新分析打开的文档。客户端支持时，服务器随后发送 `workspace/inlayHint/refresh`。                                                                                                                                                                                                                                                               |
| `client/registerCapability`（服务器到客户端）、`workspace/didChangeWatchedFiles` | 客户端支持动态注册 (dynamic registration) `workspace/didChangeWatchedFiles` 时，服务器监视每个工作区文件夹 (workspace folder) 中的 `bird.config.json`、`birdcc.config.json`、`*.conf` 与 `*.bird`。文件变化后重新分析受影响的打开文档。                                                                                                                                                                    |
| `window/showMessage`（服务器到客户端）                                           | [入口探测通知 (entry detection notification)](#notifications)；`workspace/didChangeConfiguration` 发送的设置值无效时，显示 `Invalid BIRD editor settings: <message>`。                                                                                                                                                                                                                                     |
| `window/logMessage`（服务器到客户端）                                            | 日志行，例如 `[intel] ASN database loaded: 122819 records` 与 `[project] using <path> (mode=workspace, entry=<uri>)`。                                                                                                                                                                                                                                                                                     |

服务器不实现其他请求，例如 `textDocument/rangeFormatting`、`textDocument/rename` 与 `textDocument/codeAction`。

## 诊断 [#diagnostics]

- 服务器分析每个打开文档的入口文件的 include 图，并为图中每个文件发布诊断。
- 规则诊断带有 `@birdcc/linter` 的规则代码 (rule code) 和级别 (severity)，并已按项目配置 (project configuration) 的 `linter.rules` 与 `linter.enabled` 调整。[规则](../linting/rules.mdx)列出各个代码。
- LSP 级别值如下：
  - `error`：1
  - `warning`：2
  - `info`：3
- 服务器不运行 `bird -p`。BIRD 校验由 `birdcc lint --bird` 运行。

服务器另外使用三个自己的代码：

| 代码                  | 级别        | 来源            | 消息                                                   | 报告时机                                                                                                                    |
| --------------------- | ----------- | --------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `analysis/size-limit` | 2 (warning) | `birdcc`        | `Document exceeds the analysis size limit (<n> bytes)` | 文档超出大小上限。服务器不分析该文档。诊断位于第一行。见[上限](#limits)。                                                   |
| `config/invalid`      | 1 (error)   | `birdcc-config` | `Invalid BIRD project config at <path>: <problems>`    | 项目配置未通过[校验](../configuration/reference.mdx#validation)。诊断位于配置文件上，使用该配置文件的文档不会得到其他诊断。 |
| `lsp/internal-error`  | 1 (error)   | `lsp`           | 异常的消息                                             | 分析该文档时抛出了异常。诊断位于第一行。                                                                                    |

## 设置 [#settings]

服务器从两处读取编辑器设置：

1. `initialize` 请求中的 `initializationOptions.birdcc`。值的类型错误时，`initialize` 失败。
2. 客户端支持 `workspace.configuration` 时，服务器为每个文档请求的 `workspace/configuration` 中的 `bird2-lsp` 节。这些值覆盖 `initializationOptions` 中的值。

带有 `settings["bird2-lsp"]` 或 `settings.birdcc` 的 `workspace/didChangeConfiguration` 替换来自 `initializationOptions` 的值，并重新分析打开的文档。

| 键                             | 类型    | 默认值                 | 作用                                                                                 |
| ------------------------------ | ------- | ---------------------- | ------------------------------------------------------------------------------------ |
| `enabled`                      | boolean | `true`                 | 为 `false` 时停止分析，所有请求都返回空结果。                                        |
| `performance.maxFileSizeBytes` | integer | 未设置                 | 项目没有设置 `crossFile.maxDocumentBytes` 时作为文档大小上限。两者都设置时取较小值。 |
| `intel.enabled`                | boolean | `true`                 | 为 `false` 时关闭全部 AS 号功能。                                                    |
| `intel.hover`                  | boolean | `true`                 | AS 号悬停提示 (hover)。                                                              |
| `intel.completion`             | boolean | `true`                 | AS 号补全 (completion)。                                                             |
| `intel.inlayHints`             | boolean | `true`                 | AS 号内嵌提示 (inlay hint)。                                                         |
| `typeHints.enabled`            | boolean | `true`                 | 为 `false` 时关闭函数返回类型提示。                                                  |
| `typeHints.inlay.enabled`      | boolean | `true`                 | 函数返回类型内嵌提示。                                                               |
| `formatter.engine`             | string  | `"dprint"`             | `"dprint"` 或 `"builtin"`。没有设置这个键时，`dprint` 运行失败会回退到 `builtin`。   |
| `formatter.indentSize`         | integer | 请求中的 `tabSize`     | 每级缩进的空格数，1 到 16。                                                          |
| `formatter.useTabs`            | boolean | 与 `insertSpaces` 相反 | 使用制表符缩进。                                                                     |
| `formatter.lineWidth`          | integer | `80`                   | 行宽，20 到 1000。格式化器 (formatter) 不折行。                                      |
| `formatter.safeMode`           | boolean | `true`                 | 输出的声明或解析器错误与输入不同时，拒绝该输出。                                     |

- 服务器忽略其他键。`formatter` 中的未知键是错误。
- 格式化时，项目配置中的 `formatter` 节覆盖这些设置。
- VS Code 扩展用这些键发送它的 `bird2-lsp.*` 设置。见 [VS Code 设置](./vscode.mdx#settings)。

写在 `initializationOptions` 中的设置：

```json
{
  "birdcc": {
    "intel": { "inlayHints": false },
    "typeHints": { "inlay": { "enabled": false } }
  }
}
```

同样的设置写在 `workspace/configuration` 的 `bird2-lsp` 节中：

```json
{
  "bird2-lsp": {
    "intel": { "inlayHints": false },
    "typeHints": { "inlay": { "enabled": false } }
  }
}
```

## 项目配置 [#project-configuration]

对每个文档，服务器读取文档所在目录或上级目录中最近的 `bird.config.json` 或 `birdcc.config.json`。

服务器使用下列键：

- `main`
- `workspaces`
- `includePaths`
- `crossFile`
- `linter.enabled` 与 `linter.rules`
- `formatter`

服务器忽略 `linter.withBird` 和 `bird` 节。

| 配置                | 分析的入口文件                                                                                                    |
| ------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 设置了 `workspaces` | 包含该文档的最深一层匹配目录中的 `bird.conf`，或文档所在目录中的 `bird.conf`。                                    |
| 设置了 `main`       | `main` 指定的文件。                                                                                               |
| 两个键都没有设置    | 文档本身。                                                                                                        |
| 没有配置文件        | [入口探测](../configuration/entries-and-includes.mdx#entry-detection)在工作区文件夹中选中的入口文件，或文档本身。 |

- 选中的入口文件不存在时，文档以自身为入口。
- 入口文件的 include 图到达不了某个文档时，服务器单独分析该文档。
- 设置 `crossFile.enabled: false` 时，服务器单独分析每个文档。
- [include 解析](../configuration/entries-and-includes.mdx#include-resolution)说明搜索路径与工作区根目录 (workspace root)。
- 文件监视忽略 `.git`、`node_modules`、`dist`、`build`、`target`、`coverage`、`vendor`、`.pnpm` 中的变化，除非变化的文件属于已分析的 include 图。

## 入口探测通知 [#notifications]

收到 `initialized` 后，服务器在每个根目录下没有 `bird.config.json` 或 `birdcc.config.json` 的工作区文件夹中运行[入口探测 (entry detection)](../configuration/entries-and-includes.mdx#entry-detection)，并用 `window/showMessage` 报告结果：

| 探测结论                                  | 类型    | 消息                                                                                                                |
| ----------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------- |
| `single`，置信度 (confidence) 不低于 70%  | Info    | `Auto-detected BIRD entry: <path> (<n>% confidence).`                                                               |
| `single-ambiguous`                        | Warning | ``BIRD project entry detected with low confidence: <path>. Consider creating bird.config.json with `birdcc init`.`` |
| `monorepo-multi-entry`                    | Info    | ``Multiple BIRD project entries detected. Run `birdcc init --write` to generate workspace configuration.``          |
| `monorepo-multi-role`                     | Info    | ``BIRD project with multiple roles detected. Entry: <path>. Run `birdcc init --write` for full configuration.``     |
| `not-found`，或置信度低于 70% 的 `single` | 无      |                                                                                                                     |

服务器还会发送以下消息。第一条对每个配置文件发送一次，第二条每次会话发送一次：

| 条件                                               | 类型 | 消息                                                                                                                                                     |
| -------------------------------------------------- | ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 第一次使用某个项目配置文件进行分析                 | Info | `Using <file> (<mode> mode) for cross-file analysis.` `<file>` 为 `bird.config.json` 或 `birdcc.config.json`。模式为 `workspace`、`main` 或 `document`。 |
| 没有项目配置文件，且工作区文件夹不止一个时进行分析 | Info | `No bird.config.json found in this multi-root workspace. Add workspaces/main/includePaths for better analysis.`                                          |

日志中包含探测结果，例如 `[init] Project detection: kind=single, confidence=100%, candidates=3`。

## 文档资格与上限 [#limits]

满足以下任一条件时，服务器才分析一个文档：

1. 项目配置的 `main` 指向该文档。
2. 文件名为 `bird.conf`、`bird2.conf`、`bird3.conf` 或 `bird6.conf`，可带前导点，不区分大小写。
3. 解析器在顶层找到 `router id`、`include`、`define`、`attribute`、`table`、`mpls domain`、`filter`、`function`、`template`、`graceful restart wait`、`hostname`、`timeformat`、`watchdog`，或者一个 BIRD 协议类型的 `protocol`。

对其他文档，服务器不发布诊断，所有请求返回空结果。服务器不使用文档的 `languageId`，发送哪些文件由客户端决定。

| 上限                      | 值                                                                      | 设置方式                                                                                |
| ------------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 打开文档的大小            | 文档上限与 `crossFile.maxTotalBytes` 中的较小值。文档上限默认为 2 MiB。 | `crossFile.maxDocumentBytes`、`performance.maxFileSizeBytes`、`crossFile.maxTotalBytes` |
| include 嵌套深度          | 16 层                                                                   | `crossFile.maxDepth`                                                                    |
| 一个 include 图中的文件数 | 256 个文件                                                              | `crossFile.maxFiles`                                                                    |
| 一个 include 图的大小     | 16 MiB                                                                  | `crossFile.maxTotalBytes`                                                               |
| 入口探测扫描              | 8 层目录、20,000 个文件、20,000 个目录项、2,048 个目录                  | 固定                                                                                    |
| 通配符 include 的目录读取 | 每次分析 20,000 个目录项                                                | 固定                                                                                    |

超出大小上限的文档只得到一条 `analysis/size-limit` 诊断，服务器不做其他分析。

服务器跳过超出 include 图上限的 include，并报告 `sym/undefined`。

## 在代码中启动服务器 [#api]

`startLspServer` 在当前进程中启动服务器：

```ts title="server.mjs"
import { startLspServer } from "@birdcc/lsp";

startLspServer({ asnDbPath: "/srv/asn/asn-db.bin.gz" });
```

```sh
node server.mjs --stdio
```

| 选项              | 类型    | 作用                                                     |
| ----------------- | ------- | -------------------------------------------------------- |
| `asnDbPath`       | string  | 加载这个 ASN 数据库文件，替代内置文件。                  |
| `disableAsnIntel` | boolean | 为 `true` 时不加载 ASN 数据库，AS 号功能不返回任何结果。 |

`birdcc lsp` 不传入这两个选项。[ASN 数据](./asn-data.mdx#replace)介绍数据库文件。
