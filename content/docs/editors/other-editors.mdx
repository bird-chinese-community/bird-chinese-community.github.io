Editors other than VS Code get language features from the language server that `@birdcc/cli` starts with `birdcc lsp --stdio`. Syntax highlighting and filetype detection come from separate plugins.

| Editor            | Highlighting and filetype                                      | Language server                                                                                                           |
| ----------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Neovim            | [BIRD.nvim](#neovim), Neovim 0.9 or newer                      | `vim.lsp.config`, Neovim 0.11 or newer                                                                                    |
| Vim               | [BIRD.vim](#vim), Vim 8.0 or newer                             | An LSP plugin such as vim-lsp                                                                                             |
| Helix             | None                                                           | [`languages.toml`](#helix)                                                                                                |
| JetBrains IDEs    | [TextMate grammar](#textmate-grammar) through TextMate Bundles | An LSP client plugin for user-defined servers, such as LSP4IJ, with the values in [Other LSP clients](#other-lsp-clients) |
| Other LSP clients | Depends on the editor                                          | [`birdcc lsp --stdio`](#other-lsp-clients)                                                                                |

## Install the language server [#install-the-language-server]

```sh
npm install --global @birdcc/cli
```

`birdcc` needs Node.js 22 or newer. The editor runs `birdcc lsp --stdio`, so `birdcc` must be in the `PATH` of the editor process. Otherwise, use the absolute path of the command.

[Language server](../reference/language-server.mdx) lists the capabilities and settings of the server.

## Neovim [#neovim]

[BIRD.nvim](https://github.com/bird-chinese-community/BIRD.nvim) sets the `bird2` filetype and provides syntax highlighting. Install it with lazy.nvim:

```lua
{
  "bird-chinese-community/BIRD.nvim",
  version = "^1.0.14",
  lazy = false,
  config = function()
    require("bird2").setup()
  end,
}
```

Keep `lazy = false`: the plugin must load before filetype detection runs. To use a native package instead, clone the repository into a `start` directory:

```sh
git clone https://github.com/bird-chinese-community/BIRD.nvim \
  ~/.local/share/nvim/site/pack/plugins/start/BIRD.nvim
```

BIRD.nvim sets the `bird2` filetype for:

- Files with the extensions `.bird`, `.bird2` and `.bird3`, and files that match `*.bird*.conf`.
- Files named `bird.conf`, `bird2.conf`, `bird3.conf`, `bird6.conf` or `bird-*`.
- Files below a `bird/`, `bird2/` or `bird3/` directory.
- `.conf` files whose first 200 lines contain BIRD configuration. To turn off this content check, call `require("bird2").setup({ heuristic_detect = false })`.

`:help bird2` opens the plugin documentation, and `:checkhealth bird2` checks the installation.

### Start the language server [#neovim-language-server]

Neovim 0.11 or newer configures language servers with `vim.lsp.config`. Add this to `init.lua`:

```lua title="init.lua"
vim.lsp.config("birdcc", {
  cmd = { "birdcc", "lsp", "--stdio" },
  filetypes = { "bird2" },
  root_markers = { "bird.config.json", "birdcc.config.json", ".git" },
})
vim.lsp.enable("birdcc")
```

nvim-lspconfig has no `birdcc` configuration, so you need this definition with or without nvim-lspconfig.

Neovim answers the `workspace/configuration` requests of the server from `settings`. [Language server settings](../reference/language-server.mdx#settings) lists the keys under `bird2-lsp`. For example, to turn off ASN hover:

```lua title="init.lua"
vim.lsp.config("birdcc", {
  settings = {
    ["bird2-lsp"] = {
      intel = { hover = false },
    },
  },
})
```

Without BIRD.nvim, register the filetype before you enable the server:

```lua title="init.lua"
vim.filetype.add({
  extension = { bird = "bird2", bird2 = "bird2", bird3 = "bird2" },
  filename = { ["bird.conf"] = "bird2" },
})
```

## Vim [#vim]

[BIRD.vim](https://github.com/bird-chinese-community/BIRD.vim) provides syntax highlighting, filetype detection and a filetype plugin for the `bird2` filetype. Its filetype detection uses the same rules as BIRD.nvim. Install it with vim-plug:

```vim
Plug 'bird-chinese-community/BIRD.vim'
```

Or clone it into a native package directory:

```sh
git clone https://github.com/bird-chinese-community/BIRD.vim \
  ~/.vim/pack/plugins/start/BIRD.vim
```

`:help bird2` opens the plugin documentation. To turn off the content check for `.conf` files, set `let g:bird2_heuristic_detect = 0`.

BIRD.vim does not start a language server. With the [vim-lsp](https://github.com/prabirshrestha/vim-lsp) plugin, register `birdcc` for the `bird2` filetype:

```vim title=".vimrc"
au User lsp_setup call lsp#register_server({
    \ 'name': 'birdcc',
    \ 'cmd': {server_info->['birdcc', 'lsp', '--stdio']},
    \ 'allowlist': ['bird2'],
    \ })
```

## Helix [#helix]

Add a language and a language server to `languages.toml`, either `~/.config/helix/languages.toml` or `.helix/languages.toml` in the project:

```toml title="languages.toml"
[[language]]
name = "bird2"
scope = "source.bird2"
file-types = [
  "bird",
  "bird2",
  "bird3",
  { glob = "bird.conf" },
  { glob = "bird2.conf" },
  { glob = "bird3.conf" },
  { glob = "bird6.conf" },
]
roots = ["bird.config.json", "birdcc.config.json"]
comment-tokens = "#"
language-servers = ["birdcc"]

[language-server.birdcc]
command = "birdcc"
args = ["lsp", "--stdio"]
```

Helix sends the `config` table of a language server as `initializationOptions`, and the server reads its settings from the `birdcc` key of that object. Put settings under `[language-server.birdcc.config.birdcc]`:

```toml title="languages.toml"
[language-server.birdcc.config.birdcc.intel]
hover = false
```

Helix has no grammar for BIRD, so this configuration adds language features without syntax highlighting.

## Other LSP clients [#other-lsp-clients]

Configure the client with these values:

| Item         | Value                                                                                                                                                               |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Command      | `birdcc lsp --stdio`, or `node <path>/node_modules/@birdcc/lsp/dist/server.js --stdio` when `@birdcc/lsp` is installed as a dependency.                             |
| Transport    | JSON-RPC over stdin and stdout.                                                                                                                                     |
| Files        | BIRD configuration files. The server decides from the file name and content which files to analyze; it does not use the language ID that the client sends.          |
| Root markers | `bird.config.json`, `birdcc.config.json`.                                                                                                                           |
| Settings     | `initializationOptions.birdcc`, or the `bird2-lsp` section of `workspace/configuration`. See [Language server settings](../reference/language-server.mdx#settings). |

The server analyzes the same files as the VS Code extension:

- the file that `main` points to
- files named `bird.conf`, `bird2.conf`, `bird3.conf` or `bird6.conf`
- files that contain BIRD declarations

[File association](./vscode.mdx#file-association) lists the conditions.

## TextMate grammar [#textmate-grammar]

[BIRD-tm-language-grammar](https://github.com/bird-chinese-community/BIRD-tm-language-grammar) contains the TextMate grammar `grammars/bird2.tmLanguage.json` with the scope `source.bird2`. Each release tagged `tm-v<version>` on the [releases page](https://github.com/bird-chinese-community/BIRD-tm-language-grammar/releases) includes the file. Editors and highlighters that load TextMate grammars in JSON format can use it.

### JetBrains IDEs

JetBrains IDEs load the grammar through TextMate Bundles. The bundle is the VS Code extension BIRD2 Configuration:

1. Download the latest `.vsix` file of [BIRDCC/vscode-bird2-conf](https://open-vsx.org/extension/BIRDCC/vscode-bird2-conf) from Open VSX.
2. Extract the `.vsix` file with a ZIP tool. Note the directory that contains `package.json`.
3. In the IDE, open **Settings** > **Editor** > **TextMate Bundles**.
4. Select **+** (Add) and select the directory from step 2.
5. Make sure that `bird2` is in the list and selected, then restart the IDE.

## vscode-bird2 [#vscode-bird2]

[vscode-bird2](https://github.com/bird-chinese-community/vscode-bird2) is the source of the VS Code extension BIRD2 Configuration (`BIRDCC.vscode-bird2-conf`). It contains the TextMate grammar and registers the `bird2` language for `.conf`, `.bird`, `.bird2`, `.bird3`, `.bird2.conf` and `.bird3.conf` files.

The extension provides syntax highlighting only: no diagnostics, completion or formatting. It needs VS Code 1.80 or newer and is on the [VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=BIRDCC.vscode-bird2-conf) and [Open VSX](https://open-vsx.org/extension/BIRDCC/vscode-bird2-conf).

The BIRD2 Extension Pack installs it together with BIRD2 LSP; see [VS Code](./vscode.mdx).
