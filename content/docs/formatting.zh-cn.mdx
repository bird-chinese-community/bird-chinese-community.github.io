`birdcc fmt` 用 `@birdcc/formatter` 格式化一个 BIRD 配置文件。格式化工具按块的嵌套深度缩进每一行，并规范空白字符。它不折行，也不合并、拆分或调整行的顺序。这个命令来自 `@birdcc/cli` 包，需要 Node.js 22 或更新版本。

```sh
npm install --global @birdcc/cli
```

## 检查与写入文件 [#check-and-write]

检查一个文件，命令不修改文件：

```sh
birdcc fmt bird.conf
```

```text
Format check failed. Run `birdcc fmt <file> --write` to fix.
```

文件需要格式化时，命令以退出码 1 结束；不需要格式化时，退出码为 0。`--check` 显式指定同样的检查。把格式化结果写回文件：

```sh
birdcc fmt bird.conf --write
```

输入示例与 `--write` 的结果：

```bird2 title="bird.conf (before)"
protocol bgp upstream {
local as 65001;
    neighbor 192.0.2.2 as 65002;   # transit


ipv4 {
import all;
export where net ~ [ 10.0.0.0/8+ ];
};
}
```

```bird2 title="bird.conf (after)"
protocol bgp upstream {
  local as 65001;
  neighbor 192.0.2.2 as 65002; # transit

  ipv4 {
    import all;
    export where net ~ [ 10.0.0.0/8+ ];
  };
}
```

- 不传文件参数时，`birdcc fmt` 使用最近的 `bird.config.json` 中的 `main`；没有设置 `main` 时使用 `bird.conf`。命令只格式化这一个文件，不处理它的 include 图。
- `bird.config.json` 设置了 `workspaces` 时，传入要格式化的文件。
- `--json` 输出 `{ "changed", "filePath" }`，不输出提示信息。退出码不变。
- `--write` 与 `--check` 不能同时使用。

[`fmt` 参考](./reference/cli.mdx#fmt)列出全部提示信息与退出码。[CI](./ci.mdx) 展示了在 GitHub Actions 工作流中运行 `birdcc fmt --check` 的方法。

## 格式化规则 [#rules]

两个引擎都执行以下规则：

- 按 Tree-sitter 语法树中 `{ }` 与 `[ ]` 块的嵌套深度缩进每一行。字符串和注释中的括号不影响深度。
- 把连续的空行合并为一行，删除文件末尾的空行。
- 把 `\r\n` 与 `\r` 换行符转换为 `\n`，删除行尾的空格和制表符（注释之后的除外），文件以一个 `\n` 结尾。
- 多行注释的各行保持原样，包括缩进。

在其余的行上，格式化工具还会把 `name{` 写成 `name {`，删除行末 `;` 之前的空格，并在代码与行尾 `#` 注释之间保留一个空格。代码中含有 `if`、`then`、`else`、`return` 或 `~ & | ? : ( [ ]` 之一的行是表达式行。格式化工具只修改表达式行的缩进和行尾注释前的空格。

## 格式化引擎 [#engines]

`@birdcc/formatter` 有两个执行相同规则的引擎：

| 引擎             | 实现                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------- |
| `dprint`（默认） | Rust 插件 `@birdcc/dprint-plugin-bird`，编译为 WebAssembly，通过 `@dprint/formatter` 运行。 |
| `builtin`        | `@birdcc/formatter` 中的 TypeScript 代码，使用 `@birdcc/parser` 的语法树。                  |

`builtin` 引擎把以下各行也按表达式行处理，只修改它们的缩进和行尾注释前的空格：

- 长度超过 `lineWidth` 的行。
- 有解析错误的行。
- `filter` 与 `function` 主体中的语句。
- 解析器保留为纯文本的协议语句。
- `import where` 与 `export where` 语句。

对于长度超过 `lineWidth` 的表达式行，`dprint` 引擎还会保留注释前原有的空格。

例如，在 `filter` 主体中，`dprint` 引擎把 `bgp_med = 100   ;` 写成 `bgp_med = 100;`，`builtin` 引擎保留这一行的原样。

用 `--engine` 为单次运行选择引擎，或用 `bird.config.json` 中的 `formatter.engine` 为每次运行选择引擎：

```sh
birdcc fmt bird.conf --write --engine builtin
```

`--engine` 与 `formatter.engine` 都没有设置且 `dprint` 引擎失败时，birdcc 改用 `builtin` 引擎重新格式化文件，并向 stderr 输出 `Formatting with @birdcc/formatter failed, falling back to builtin formatter: <reason>`。指定了引擎时，birdcc 报告这次失败，并以退出码 1 结束。

## 安全模式 [#safe-mode]

安全模式默认开启。格式化工具返回修改后的文本之前，用 `@birdcc/parser` 分别解析输入和输出，并比较两次解析的结果：

- 去掉源码位置、把文本值中的空白字符合并后的声明树。
- 每个解析错误的代码和消息。

两者不一致时，格式化失败并报告 `Formatter safe mode rejected output because semantic fingerprint changed`，文件保持不变。`dprint` 引擎还会在插件内部再做一次检查：比较两棵 Tree-sitter 语法树的节点类型、子节点数量、缺失节点和词法单元文本，不一致时报告 `Formatter safe mode rejected output because syntax or token content changed`。

- 含有语法错误的文件，只要格式化前后的解析错误相同，就会被格式化。
- 输出与输入完全相同时，不运行检查。

要关闭安全模式，在 `bird.config.json` 的 `formatter` 部分设置 `"safeMode": false`。

## 格式化选项 [#options]

`birdcc fmt`、语言服务器和 VS Code 扩展都读取 `bird.config.json` 的 `formatter` 部分：

```json title="bird.config.json"
{
  "main": "bird.conf",
  "formatter": {
    "engine": "dprint",
    "indentSize": 4,
    "lineWidth": 100,
    "safeMode": true
  }
}
```

| 键           | 默认值     | 取值                    | 说明                                                                         |
| ------------ | ---------- | ----------------------- | ---------------------------------------------------------------------------- |
| `engine`     | `"dprint"` | `"dprint"`、`"builtin"` | 格式化引擎。见[格式化引擎](#engines)。                                       |
| `indentSize` | `2`        | 1 到 16                 | 每级缩进的空格数。                                                           |
| `useTabs`    | `false`    | `true`、`false`         | 每级缩进使用一个制表符。                                                     |
| `lineWidth`  | `80`       | 20 到 1000              | 长度超过此值的行保留更多原文。见[格式化引擎](#engines)。格式化工具从不折行。 |
| `safeMode`   | `true`     | `true`、`false`         | 解析结果与输入不一致时拒绝输出。见[安全模式](#safe-mode)。                   |

`birdcc fmt` 没有设置缩进或行宽的命令行选项。入口文件使用 2、4 或 8 个空格缩进时，`birdcc init` 会写入 `formatter.indentSize`。[配置参考](./reference/configuration.mdx#formatter)介绍完整的 `formatter` 部分。

## 使用 dprint 插件 [#dprint]

dprint CLI 可以直接加载 `@birdcc/dprint-plugin-bird`，适用于已经用 dprint 格式化其他文件的仓库。`npm:` 插件写法和叠加生效的 `associations` 需要 dprint 0.55.0 或更新版本。以下示例已在 dprint 0.64.3 上测试。

<Steps>

<Step>

### 安装 dprint 与插件

```sh
npm install --save-dev dprint @birdcc/dprint-plugin-bird
```

</Step>

<Step>

### 在 dprint.json 中添加插件

```json title="dprint.json"
{
  "birdcc": {
    "lineWidth": 100,
    "indentWidth": 2,
    "useTabs": false,
    "safeMode": true
  },
  "plugins": ["npm:@birdcc/dprint-plugin-bird/dist/dprint-plugin-bird.wasm"]
}
```

不带版本号的 `npm:` 写法从 `node_modules` 加载这个包。dprint 从 `dprint.json` 所在目录开始向上查找。

</Step>

<Step>

### 检查并格式化文件

```sh
npx dprint check
npx dprint fmt
```

`dprint check` 为每个需要格式化的文件输出差异，并以非零退出码结束（dprint 0.64.3 为 20）。`dprint fmt` 写入文件。

</Step>

</Steps>

插件选项写在 `dprint.json` 的 `birdcc` 对象中。dprint 不读取 `bird.config.json`。

| 键            | 默认值                                        | 说明                                                                           |
| ------------- | --------------------------------------------- | ------------------------------------------------------------------------------ |
| `lineWidth`   | dprint 配置中的 `lineWidth`，未设置时为 80    | 长度超过此值的表达式行还会保留注释前原有的空格。插件从不折行。                 |
| `indentWidth` | dprint 配置中的 `indentWidth`，未设置时为 2   | 每级缩进的空格数。`bird.config.json` 中对应的键是 `indentSize`。               |
| `useTabs`     | dprint 配置中的 `useTabs`，未设置时为 `false` | 每级缩进使用一个制表符。                                                       |
| `safeMode`    | `true`                                        | 运行插件内部的检查。`@birdcc/formatter` 基于 `@birdcc/parser` 的比较不会运行。 |

- `birdcc` 对象中出现未知的键时，dprint 报告 `Unknown property in configuration` 并停止。JSON schema 见 [`schemas/dprint-plugin-bird.schema.json`](https://github.com/bird-chinese-community/BIRD-LSP/blob/main/schemas/dprint-plugin-bird.schema.json)。
- 插件格式化所有扩展名为 `.conf` 或 `.bird` 的文件。要排除其他 `.conf` 文件或加入更多文件名，设置 `associations`：

  ```json title="dprint.json"
  {
    "birdcc": {
      "associations": ["!**/nginx.conf", "**/*.bird3"]
    }
  }
  ```

- 另外两种插件写法加载同一个模块：文件路径 `"./node_modules/@birdcc/dprint-plugin-bird/dist/dprint-plugin-bird.wasm"`，以及由 dprint 从 npm registry 下载的固定版本 `"npm:@birdcc/dprint-plugin-bird@1.0.0/dist/dprint-plugin-bird.wasm"`。

## 在编辑器中格式化 [#editors]

编辑器集成使用 `@birdcc/formatter`，并读取 `bird.config.json` 的 `formatter` 部分。它们不格式化没有 BIRD 内容的 `.conf` 文件，例如 `nginx.conf`。[文件关联](./editors/vscode.mdx#file-association)列出判定条件。

<Tabs items={["VS Code", "其他编辑器"]}>

<Tab value="VS Code">

BIRD2 LSP 提供格式化文档（Format Document）和格式化选定内容（Format Selection），并为 `bird2` 语言把 `editor.defaultFormatter` 设为 `BIRDCC.bird2-lsp`。格式化选定内容会格式化整个文件，只应用选区内的修改。

扩展按以下顺序取每个选项，使用第一个设置了该选项的来源：

1. `bird.config.json` 的 `formatter` 部分。
2. 设置项 `bird2-lsp.formatter.engine` 与 `bird2-lsp.formatter.safeMode`。
3. 编辑器的制表符宽度和缩进方式。

`lineWidth` 只来自 `bird.config.json`，默认值为 80。格式化失败时，文件保持不变，`BIRD2 LSP` 输出通道中会显示失败原因。[VS Code 设置](./editors/vscode.mdx#settings)列出这些设置项。

</Tab>

<Tab value="其他编辑器">

语言服务器响应 `textDocument/formatting`，返回一个覆盖整个文档的修改。它不支持范围格式化。在 Neovim 中，`vim.lsp.buf.format()` 发送这个请求。

服务器按以下顺序取每个选项，使用第一个设置了该选项的来源：

1. `bird.config.json` 的 `formatter` 部分。
2. 客户端发送给服务器的编辑器设置中的 `formatter` 对象。
3. 格式化请求中的 `tabSize` 与 `insertSpaces`。

格式化失败时，服务器返回错误 `BIRD formatting failed: <reason>`。[语言服务器设置](./reference/language-server.mdx#settings)列出这些设置项。

</Tab>

</Tabs>
